### Warnings

#### `PageToken` is documented as opaque and pinned, but is a forgeable public case class
**Location:** `core/src/works/iterative/claude/core/log/model/PageToken.scala:29`, consumed at `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:65-76,140`
**Problem:** `PageToken`'s scaladoc says "Treat it as opaque: obtain one from a page and hand it back," and the port's `entriesBefore` doc says the token "is pinned to the transcript it was minted against." Nothing enforces that. `PageToken` is a plain public `final case class(sessionId, source: os.Path, offset: Long)` — any caller in any module can construct one directly with an arbitrary `source`/`offset` and pass it to `entriesBefore`.
**Impact:** The whole point of pinning (`PageSourceMoved` rather than reading a stale offset against the wrong file) is a runtime check against a value the type system does nothing to protect. This is the same class of concern the id-validation choke point (`ArchivePaths.validateId`) was built to close for `sessionId`/`parentToolUseId`, but here the equivalent invariant for the cursor is comment-only. It also weakens the "no attributed store" boundary from decision 8: a token is effectively a raw filesystem pointer handed to library consumers with no construction-time guard.
**Recommendation:** Make `PageToken`'s constructor private to the `log` package (or to `ZioConversationArchive`/a factory in `core.log`), and mint it only where `readPage` currently builds it, e.g.:

```scala
final case class PageToken private (sessionId: SessionId, source: os.Path, offset: Long)
object PageToken:
  private[log] def apply(sessionId: SessionId, source: os.Path, offset: Long): PageToken =
    new PageToken(sessionId, source, offset)
```

so "opaque" is a compiler-enforced property, not a docstring promise.

#### Archive reaches into an unrelated service's full constructor to reuse one config-independent method
**Location:** `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:39,158-159`
**Problem:** `locateSubAgentTranscript` calls `index.listSubAgents(projectDirOf(rec.root), sessionId.value)` on an index built via `ZioConversationLogIndex.make(None, os.home)`. `listSubAgents` (verified in `ZioConversationLogIndex.scala:38-61`) never reads `configDirOverride`/`home` — only `listSessions` and `listSubAgentsFor` do. The comment at line 36-38 explicitly flags the placeholder args as safe today, which is itself the tell: the archive is coupled to a collaborator's whole constructor shape to reach one method that doesn't need that shape.
**Impact:** This is a hidden, comment-maintained invariant rather than a structural one. If `ZioConversationLogIndex`'s constructor or `listSubAgents` ever starts using `configDirOverride`/`home` (e.g., for a future feature), this call site silently breaks with wrong-looking-but-compiling behavior, and nothing short of re-reading this comment would catch it during that future change.
**Recommendation:** Extract the sub-agent-listing logic (or expose it) so it doesn't require instantiating an index with irrelevant config — e.g. a companion-object function `ZioConversationLogIndex.listSubAgents(projectPath, sessionId): Task[Seq[SubAgentMetadata]]` that doesn't need `make`, or move the shared logic to a place both call sites can reach without pretend arguments.

## ZIO Framework Review

### Critical Issues

None found.

### Warnings

#### Read path doesn't tolerate the vendor tree vanishing between `locate` and the actual read
**Location:** `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:56-76` (`lastEntries`, `entriesBefore`), also affects `entries`/`subagentEntries` (lines 50-54, 78-86) and `mirror` (88-95)

**Problem:** Every read path first resolves the session with `locate` (one `ZIO.attemptBlocking` doing `os.exists`/`os.isFile` stats), then performs the actual read in a *second*, separate `attemptBlocking` (`readPage`, `transcriptStream`, `runMirror`). If the vendor tree is pruned in the gap between those two calls — which is exactly the concurrent scenario this whole vendor-then-mirror design is built to survive (see the doc comment on `ConversationArchive`: "falling back to the archive mirror once the vendor tree has been pruned") — the second call throws a raw `NoSuchFileException`/similar, and `toArchiveError` (line 283-287) has no case for it, so it folds into a generic `ArchiveIOError` rather than `SessionNotFound` or a mirror-fallback retry.

**Impact:** A page/tail/mirror request racing a live prune gets an opaque I/O error instead of the graceful vendor→mirror fallback the feature promises. The existing tests (`forSession and entries fall back to the archive when the vendor tree is pruned`, `mirror is a no-op when the vendor tree is gone`) only prune *between* two separate top-level calls; none exercise deletion inside the `locate`-then-read gap of a single call, so this gap is untested.

**Recommendation:** Either (a) special-case the "file vanished" exception in `toArchiveError` (or in `readPage`/`transcriptStream`) to re-run `locate` once and retry against whatever it now resolves to before failing, or (b) explicitly accept the residual race as out of scope and add a regression test that deletes the vendor file between `locate` and the read to document the current (opaque-error) behavior.

#### `runMirror`'s file-size listing isn't guarded like the copy/extend actions are
**Location:** `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:175-208` (`runMirror`), `253-257` (`listing`)

**Problem:** `runMirror` builds `source`/`mirror` listings via `listing(...)`, which calls `os.size(path)` for every file returned by `sourceFiles`/`mirrorFiles` (line 256-257). Unlike every action in the `foldLeft` (`Copy`, `Recopy`, `Extend`), which is wrapped in the `guarded` `Try` that turns a failure into a per-file `report.failed` entry, the `listing` step has no such protection. If a source file disappears between the `os.walk`/`os.isFile` filter in `walkRegularFiles` and this `os.size` call — again, the exact vendor-pruning race this feature targets — the whole `ZIO.attemptBlocking(runMirror(record))` throws and is turned into a single opaque `ArchiveIOError`, discarding whatever partial mirror progress would otherwise have been reported.

**Impact:** A prune racing a mirror run loses the "per-file failure, not whole-run failure" guarantee that the rest of `runMirror` is explicitly designed to provide (see the `guarded` helper's purpose and the "mirror records a per-file copy failure instead of aborting the run" test).

**Recommendation:** Wrap the per-file `os.size` lookup in `listing` with the same tolerant-of-missing-file handling used for the copy/extend actions (e.g., skip a file that vanished before it was sized, rather than letting the exception escape the whole blocking computation).

### Suggestions

#### Every public method independently re-resolves the session via `locate`
**Location:** `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:45-95, 100-108`

**Problem:** `forSession`, `entries`, `lastEntries`, `entriesBefore` (via `resolveMainTranscript`), `mirror`, and `subagentEntries` (via `locateSubAgentTranscript`) each call `locate`, which is its own `ZIO.attemptBlocking` doing a fresh vendor+mirror stat. A caller that calls `forSession` then `entries` then `mirror` back-to-back (as `ZioConversationArchiveIntegrationTest` does) re-resolves the session three times.

**Impact:** Not a correctness issue, but `lastEntries`/`entriesBefore` look purpose-built for polling a live, actively-growing session (tailing), where the repeated stat-of-two-directories cost is paid on every poll.

**Recommendation:** Consider a variant that accepts an already-resolved `SessionRecord` for call sites that already have one, or memoize the resolution within a single logical request, if this path turns out to be hot.

#### Tail reader reopens the file once per backward block
**Location:** `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:119-142` (`readPage`, the `(at, count) => os.read.bytes(path, at, count)` closure passed into `ByteRangeReader.readFully`/`BackwardLineReader.lastLines`)

**Problem:** `BackwardLineReader.readBackTo` can call `readBlock` multiple times (once per 64 KB step) while growing the buffer backward. Each call goes through `os.read.bytes(path, at, count)`, which opens and closes the file per invocation.

**Impact:** Minor I/O overhead per `lastEntries`/`entriesBefore` call, proportional to how many blocks are needed to satisfy `limit` — usually small, but avoidable.

**Recommendation:** Since the whole operation already runs inside one `ZIO.attemptBlocking`, open a single channel (`RandomAccessFile`/`SeekableByteChannel`) for the duration of `readPage` and read ranges from it instead of re-opening per block.

</review>

## Warnings

#### `ZioConversationArchive` is accumulating two unrelated responsibilities
**Location:** `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:29-293`
**Problem:** The class now mixes two largely independent capability groups behind one 294-line, ~24-method class:
- **Read-path resolution** (new in this PR): `locate`, `resolveMainTranscript`, `isTranscript`, `readPage`, `transcriptStream`, `locateSubAgentTranscript`, `projectDirOf`, plus the public `forSession`/`entries`/`lastEntries`/`entriesBefore`/`subagentEntries`.
- **Mirror/custody file management** (pre-existing, untouched in shape by this PR): `runMirror`, `sourceFiles`, `mirrorFiles`, `walkRegularFiles`, `listing`, `copyWhole`, `extendInPlace`, `restrictArchiveDirs`, `regularFile`, plus the public `mirror`.

These two groups share almost no private helpers (only `toArchiveError`/`failureMessage`/`ArchivePaths` calls are common) and reason about very different concerns: streaming/paging a transcript vs. diffing and copying a file tree with permission hardening. This PR's read-path growth (adding `lastEntries`/`entriesBefore`/`locate`/`readPage`) is exactly the kind of addition the skill flags as pushing a class past the "focused service" threshold (>200 lines, method count climbing past ~20).
**Impact:** As more read-path features land (this PR's own review context anticipates more), every future change has to be reviewed against the mirror logic's invariants too (e.g. `restrictArchiveDirs`'s POSIX permission tightening, `extendInPlace`'s prefix-check), even though they're unrelated to what's being changed. The class is hard to name concisely ("locates, reads, tails, and mirrors" — per its own updated PURPOSE comment) and a single-sentence description no longer captures one responsibility.
**Recommendation:** Extract the mirror/copy machinery into its own collaborator (e.g. `ArchiveMirror`/`SessionMirrorer`) that `ZioConversationArchive` composes rather than implements inline:

```scala
class ArchiveMirror(config: ArchiveConfig):
  def mirror(record: SessionRecord): Task[MirrorReport] = ...
  // runMirror, sourceFiles, mirrorFiles, walkRegularFiles,
  // listing, copyWhole, extendInPlace, restrictArchiveDirs, regularFile live here

class ZioConversationArchive private (config: ArchiveConfig, archiveMirror: ArchiveMirror)
    extends ConversationArchive[[A] =>> IO[ArchiveError, A]]:
  // locate, readPage, transcriptStream, locateSubAgentTranscript, public read API
  def mirror(sessionId: SessionId): IO[ArchiveError, MirrorReport] =
    locate(sessionId).flatMap:
      case Some(record) if record.root == RecordRoot.Vendor =>
        archiveMirror.mirror(record).mapError(toArchiveError)
      case Some(_) => ZIO.succeed(MirrorReport.empty)
      case None    => ZIO.fail(SessionNotFound(sessionId.value))
```
This keeps `ZioConversationArchive` focused on "resolve and read a session," each collaborator independently testable, and leaves room for the read-path (which this PR's context says is still growing) to expand without further bloating the mirror logic's neighbor.

**Location:** `core/src/works/iterative/claude/core/log/ConversationArchive.scala:71-74`
**Problem:** The review context explicitly calls out that "vendor-absent mirror semantics must be stated exactly" on `ConversationArchive`. The trait's own scaladoc for `mirror` says only:

```scala
/** Idempotently mirrors the whole session tree into the archive directory,
```

#### New archive read fallback does not guard against symlinks, unlike the mirror-write path
**Location:** `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:100-117` (`locate`/`isTranscript`), and `ZioConversationArchive.scala:147-165` (`locateSubAgentTranscript` → `index.listSubAgents` in `zio/src/works/iterative/claude/zio/log/ZioConversationLogIndex.scala:38-61`)

**Impact:** If anything is ever able to place a symlink inside `archiveDir` (loose permissions before the first `mirror()` call sets 0700, a shared/multi-tenant archive location, or any future code path that writes into the archive without going through `runMirror`'s symlink-excluding listing), a subsequent read call will transparently follow it and return the target file's bytes as if they were conversation entries — reading arbitrary local files outside `archiveDir`. Custody being "one-directional" today limits how a symlink would get there, but the read path itself provides no defense-in-depth against it, unlike the write path.
**Recommendation:** Mirror the write-side guard on the read side — reject (or refuse to resolve) a candidate whose `mainTranscript`/`treeDir`/sidechain file is a symlink, e.g.:
```scala

  !os.isLink(path) && os.exists(path) && os.isFile(path)
```
and apply the same `!os.isLink` check inside `ZioConversationLogIndex.listSubAgents`'s file listing.

#### No upper bound on `limit`/no cap on backward-scan cost when newlines are sparse or absent
**Location:** `core/src/works/iterative/claude/core/log/BackwardLineReader.scala:97-110` (`readBackTo`), driven from `ZioConversationArchive.scala:119-142` (`readPage`, called by `lastEntries`/`entriesBefore` with a caller-supplied `limit: Int`)
**Problem:** `readBackTo` only stops when `curStart <= 0` or the buffer holds more newlines than `limit`. Neither `lastEntries` nor `entriesBefore` caps `limit` (a `Int.MaxValue` or any large value is accepted as-is), and independent of `limit`, a region with few/no `0x0A` bytes (a corrupted, non-JSONL, or maliciously oversized single line) forces the loop to keep prepending `blockSize` (64 KiB) chunks via `block ++ buffer` until `curStart <= 0`, i.e., the *entire file* is read into memory with O(n²) copy cost — contradicting the type's own doc/PURPOSE claim that "cost is proportional to the page, not the region." This exact "line longer than any block" scenario is only tested at trivial (bytes-scale) size (`BackwardLineReaderTest.scala:73-78`, `:47-51`), not at a size that would demonstrate the resource cost.
**Impact:** A caller (or, once this SDK's paging API is wrapped by any future HTTP/CLI surface that passes through a user-supplied page size) can trigger unbounded memory allocation and quadratic CPU cost against a large or malformed transcript file, a straightforward DoS vector for the described "byte-range reads bounded" concern.
**Recommendation:** Enforce a maximum `limit` at the `ConversationArchive` API boundary (reject/clamp before calling `readPage`), and/or bound `BackwardLineReader.lastLines` by a maximum scan-back byte budget (in addition to the newline-count condition) so a pathological region degrades to a bounded/partial read (or an explicit error) instead of buffering the whole file.

#### Vendor-tree fallback can silently mask a permission/IO problem as "already pruned"
**Location:** `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:100-117` (`locate`, `isTranscript`)
**Problem:** `locate` decides between vendor and archive purely via `isTranscript(path) = os.exists(path) && os.isFile(path)`. `os.exists`/`java.nio.file.Files.exists` is specified to return `false` whenever the JVM cannot *determine* existence (e.g. a permission-denied parent directory), not just when the file is truly absent. Previously (pre-diff) a permission problem on the vendor tree surfaced as `SessionNotFound` for the whole operation; now the same condition is indistinguishable from a legitimately-pruned vendor tree and the call **silently and successfully** falls through to the archive mirror, potentially serving stale data without any signal that the vendor tree was actually unreadable rather than absent.
**Impact:** A real infrastructure fault (broken mount, wrong permissions, transient EACCES) is swallowed and reinterpreted as an expected business condition ("vendor was pruned"), which is exactly the "silent failure via `Option`/exists-check" anti-pattern this skill flags. The two-root fallback introduced by this PR is what makes the blast radius worse — before, this ambiguity only ever produced `SessionNotFound`; now it also happens to change `mirror`'s behavior (no-op, "custody is one-directional") since `record.root` will read as `Archive`.
**Recommendation:** If distinguishing "doesn't exist" from "couldn't check" matters here (it does, since it changes both read source and mirror custody), don't rely on `os.exists`'s existence semantics alone — catch and classify `os.exists`/`os.isFile` failures explicitly, or at minimum note this known blind spot in `locate`'s doc so a future reader understands the fallback is exists-based, not existence-versus-error-based.

#### `lastEntries`/`entriesBefore` silently misreport "reached the start" for a non-positive `limit`
**Location:** `core/src/works/iterative/claude/core/log/BackwardLineReader.scala:62` (`if limit <= 0 || regionEnd <= 0 then Tail(Vector.empty, None)`); consumed unchanged in `zio/src/works/iterative/claude/zio/log/ZioConversationArchive.scala:119-142` (`readPage`); public signatures at `core/src/works/iterative/claude/core/log/ConversationArchive.scala:51,60` (`lastEntries`, `entriesBefore`)
**Problem:** `limit <= 0` and `regionEnd <= 0` (genuinely empty file) are folded into the same result: `Tail(Vector.empty, older = None)`. **Impact:** This is reachable directly through the public `ConversationArchive` port (`limit: Int` is unvalidated), and produces a *false success* rather than a typed error — the exact "no silent failures" violation this skill checks for, just inverted (silent false-positive termination instead of a swallowed exception). `BackwardLineReaderTest.scala:112-114` only asserts `.lines` for `limit = 0`, not `.older`, so the mismatch is untested.

#### `PageToken` claims opacity in its doc comment but is a fully public, freely-constructible case class
**Location:** `core/src/works/iterative/claude/core/log/model/PageToken.scala:1-33`
**Problem:** The Scaladoc says "Treat it as opaque: obtain one from a page and hand it back to fetch the previous page," but `PageToken` is a plain `final case class` with public `sessionId`, `source: os.Path`, and `offset: Long` fields and a public constructor. **Impact:** Today `ZioConversationArchive.entriesBefore` happens to be safe because it re-derives the current path independently and only proceeds when it equals `token.source` (so a forged token can only succeed if it matches the legitimately resolved path) — but that safety is incidental to this one adapter, not guaranteed by the port. **Recommendation:** Make the opacity real rather than documented. Options, roughly in order of effort:
```scala
// Minimal: private constructor + package-private factory, so only this
// package can mint one; consumers can still pattern-match today but can't

final case class PageToken private (
    sessionId: SessionId,
    source: os.Path,
    offset: Long
)
object PageToken:
  private[log] def apply(sessionId: SessionId, source: os.Path, offset: Long): PageToken =
    new PageToken(sessionId, source, offset)

// Stronger: hide the fields entirely behind an opaque type / private case
// class, exposing only what a caller needs (sessionId) and nothing that
// would leak host filesystem structure if ever serialized.
```

#### Interface cohesion: custody (mirror) and read/paging concerns are bundled, and the only real consumer already only needs one half
**Location:** `core/src/works/iterative/claude/core/log/ConversationArchive.scala:30-75`, `zio/src/works/iterative/claude/zio/internal/cli/SessionArchiveHook.scala:69-72`
**Problem:** The trait's own doc frames it as "Custody of a session's record: locate it, read its conversation entries..., and mirror the whole tree." Before this PR that was two cohesive concerns sharing one resolution algorithm (locate vendor-then-mirror, then either stream or copy).
